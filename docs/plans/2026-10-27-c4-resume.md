## 1. What the Mac sets on the bench (the only settings this needs)

- **One `main` ruleset**, the production one with one change, so the check can see code-owner review and the lane can
  still push the overlay commit straight to the bench's `main`:

  ```sh
  REPO=morndo/morndo-release-test
  gh api -X POST repos/$REPO/rulesets --input - <<'EOF'
  {"name":"main: pull request and code owners","target":"branch","enforcement":"active",
   "conditions":{"ref_name":{"include":["~DEFAULT_BRANCH"],"exclude":[]}},
   "rules":[{"type":"pull_request","parameters":{"required_approving_review_count":1,"require_code_owner_review":true,
     "dismiss_stale_reviews_on_push":true,"require_last_push_approval":false,"required_review_thread_resolution":false}}],
   "bypass_actors":[{"actor_id":5,"actor_type":"RepositoryRole","bypass_mode":"always"}]}
  EOF
  ```

  Production's bypass is `pull_request` (bypass only on a pull request); `always` is needed on the bench because the
  overlay arrives by a direct push. GitHub documents `pull_request` as "an actor can only bypass rules on pull
  requests" and `always` as the default (https://docs.github.com/en/rest/repos/rules, read 2026-10-27). The check
  then prints the same `WARN:` as production with `--allow-main-bypass`. **Not wanted:** production's second ruleset
  (required checks: the bench runs no `ci`, so every push would be refused), and no `non_fast_forward` rule is
  needed (the overlay push is a fast-forward, step 4). Without this ruleset the rehearsal still runs; P9 then ends
  with one known extra line instead of a `WARN:`.
- **Administrator bypass off on `release`, `feed`, `promote`, `withdraw`** (the checkbox of step 4 of
  `docs/release-settings.md`). The runs wait for the tap either way; it is needed so the check's end state (P9) is
  "only the release App's lines", as in production, and so no admin can wave a bench run through. `github-pages` may
  keep it.
- **Decision 1 above:** the reviewer on `github-pages` off in both repositories (recommended), or kept.
- Nothing else: no tag ruleset and no `release-please` environment on the bench (the stand-in tags with the run's
  token, and a tag ruleset would block it).

## 3. The rehearsal, as commands

Names: compose project `c4-rehearsal`; machines `cp1.rehearsal.test` (P3 to P6, P10), `cp2.rehearsal.test` (P7, a
clean `latest` install after the withdrawal), `cp3.rehearsal.test` (P8, a clean `stable` install); network
`c4-rehearsal_net`, a bridge. `.test` is reserved for testing and never resolves on the internet (RFC 6761 §6.2). The
versions are examples: `0.1.2` is the first free one on the bench, `0.1.3` the second.

**Build the bench tree and the push (steps 4 and 5).** All under the scratch area, never in a checkout of production:

```sh
S=<scratch>/c4-5; CAND=$(git -C <worktree> rev-parse origin/main)       # main after #169
sh scripts/release/bench-overlay.sh "$CAND" --version 0.1.2 --trust "$S/trust" --root-signer "$S/root.allowed" --out "$S/tree"
sh scripts/release/bench-overlay.sh --audit "$CAND" "$S/tree"            # must say ok; the diff it prints is the record
git clone https://github.com/morndo/morndo-release-test "$S/bench" && cd "$S/bench"
git fetch https://github.com/morndo/morndo "$CAND"                       # the candidate's history (the downgrade tests read it)
GIT_INDEX_FILE="$S/index" git --work-tree="$S/tree" add -A
TREE=$(GIT_INDEX_FILE="$S/index" git write-tree)
C=$(git commit-tree "$TREE" -p origin/main -p "$CAND" -m "chore: bench: morndo main at ${CAND%"${CAND#????????}"} with the overlay (0.1.2)")
git diff --stat origin/main "$C" | tail -1; git push origin "$C:refs/heads/main"   # only after the manager's word
```

The commit has the bench's `main` as its first parent, so the push is a fast-forward. The second release is the same
with `--version 0.1.3` and `-p origin/main` (the bench's new head) only.

**The machines (step 6, P3).** `compose.yaml` from C4-5b, in substance:

https://docs.docker.com/reference/compose-file/services/, read 2026-10-27.)

P4 to P10 follow the C4-5 plan's section 3 unchanged (P7: `docker compose --profile p7 up -d cp2`, P8: `--profile

step is never built on.
