What the spike settles, and what changes in the plan:
1. **The hook fires in `-p`** and its stdin is the documented JSON: `session_id`, `transcript_path`, `cwd`, `prompt_id`, `effort`, `hook_event_name`, `error`, `last_assistant_message`; **`error_details` was never present** in any case here. Payloads are saved, with the ids and paths replaced, in `apps/connections/test/fixtures/stopfailure/`.
2. **The plan's guess was wrong in two places.** (a) The credit refusal arrives as `billing_error`, but Claude Code's own wording is `Credit balance is too low` (not "…balance too low", and not the API's long sentence; the classifier's `CREDIT` pattern accepts "credit balance (is )?too low", so it matches). (b) `billing_error` is not the only code that carries a refusal worth acting on: a 402 and the spend-limit 400 both arrive as `unknown`. So **the `error` field is only a hint; the text is classified for every code**. The status is read from the CLI's own prefix (`API Error: 402 …`, `(429)`), anchored at the start of the text.
3. **No status in the text for the credit case, and no `error.type` anywhere.** The 402 row has no type, so a status 402 from the prefix stands for `billing_error` (the plan's table row 2 maps a 402 `billing_error` to exhausted). A 429 that names `enforced_spend_limit_reached` (the tier's cap) cannot be told from a plain 429 here, so it reads as `limited` (recorded, nothing happens): the safe direction, stated as a limit.
4. **A hold looks like a 403 `authentication_failed`** whose text holds `account_on_hold`; the classifier's `HELD` rule (a 401/403 whose text names the identifier) gives `failing(held)`. A bare 401 or 403 is `failing(rejected)` / `failing(denied)`.
5. Hook payloads carry the session's `transcript_path` and `cwd`: neither is read, stored or echoed (KP12).

## Steps (tests first and committed red, then the code, then a negative control per guard)

The executor is a Cursor model through `agent -p --force --trust` from a transient user unit; at most two rounds per step; every diff is read by the lane and the commit author is checked. Gates per step: `tsc` (domain, protocol, connections, `tsconfig.tests.json`), `oxlint`, `scripts/negative-controls.ts --check`.

### A. The hook report-back (plan 3.4 (2))
1. **Adapter** (`apps/connections/test/outcome-hook.test.ts`, the eight saved payloads): `signalFromHook(payload)` returns a `ProviderSignal` or null (`null` for a payload that is not a `StopFailure` object, for an `error` that is not a string, for text over 4 KB: no signal, no guess). Named: `the credit payload is exhausted(credit) through the dialect`, `a 402 payload is exhausted(credit)`, `the spend-limit payload is exhausted(spend-limit) with the date it names`, `a 429 payload is limited`, `a 401 payload is failing(rejected), a 403 payload is failing(denied), a hold is failing(held)`, `a 529 payload (server_error) gives no signal`, `the error code is only a hint: the same text under another code classifies the same`, `a status is read only from the CLI's own prefix: a credit phrase later in a long text with a different status is not exhausted` (control: a reader that takes any 3 digits fails it), `last_assistant_message, error_details, transcript_path and cwd are in no part of the signal beyond the 256-character excerpt the classifier already clips`, `a payload that is not a StopFailure event gives null`.
2. **Service** (`apps/connections/test/key-pool-hook-service.test.ts`): `reportHook(pool, target, payload, observedAt, by)` classifies with the pool's dialect, raises the `unclassified` alert for an unmatched 4xx (status and type only, as `reportSignal`), and applies a mark through the same door as `report`/`reportByGrant`. Named: `a hook by grant marks the grant's member exhausted once`, `a hook by member marks that member`, `a rate-limit hook records nothing and changes nothing`, `a hook from a process that does not hold the grant is refused before anything is applied`, `a hook for a deleted pool or a missing grant says its word`, `a hook that finds the member dry in the hand-off window names the current member as the one to suspect (KP18)`, `a payload with a planted secret in last_assistant_message and error_details leaves it in no event, alert, pool body or return value`.
3. **CLI and launcher** (`apps/connections/test/keypool-hook-cli.test.ts`, through the real bin; the fake runtime fixture runs the hook command the settings name, with a payload on stdin, as Claude Code would). `keypool report <pool> (--grant G | --member M) --from-hook` reads stdin (at most 64 KB; more is `too_big`), prints one JSON line of words (`{"pool","outcome"}`), never the text, and exits 0 for any well-formed payload (the hook's own exit code is ignored by Claude Code). Named: `a pooled run's settings carry a StopFailure hook that names the pool and the grant` (and no other key besides today's), `the hook reports a credit refusal while the run's own result is a success, so only the hook can have marked the member`, `the next helper call after a hook report hands the run to the next member`, `--from-hook with --member marks that member (a hand-written settings file)`, `--from-hook refuses --lease, --outcome and --reason`, `stdin that is not JSON, or is too large, exits 1 with a word and changes nothing`, `a payload with a planted secret in every field leaves it in stdout, stderr, every file of the home, the pool's events and the alert file`, `a non-pooled run's settings carry no hook`, `the hook command line holds no key`.

### B. Sinks and the deny list (plan 3.6, sinks; section 5)
4. **Domain** (`packages/domain/test/key-pool-sinks.test.ts`): `KeyPool.sinks` (older saved pools load with `[]`). `addKeySink` / `removeKeySink`, the principal's (KP10: widening, since a sink is where a key will be written). Named: `kp20 a sink is an absolute, normalised path of safe characters, at most 16 per pool and unique`, `kp20 a path with .., a trailing slash, a control character, a space or a glob character is refused`, `kp20 a sink is the principal's: a lane may not add or remove one`, `kp20 the sidecar of a sink (<path>.member) is not itself a sink`, `sinks are in the saved body, a pool saved before them loads with none`, `a sink path is in no event` (events carry the pool, the time, the command id and a count).
5. **Service and CLI** (`apps/connections/test/key-pool-sinks-service.test.ts`, `keypool-sink-cli.test.ts`): `keypool sink add|remove|list <pool> [path]`. 6. **The deny list** (`apps/connections/test/keypool-deny-cli.test.ts`, and a unit on the argv builder): every sink path of every pool, and every sidecar, is in `permissions.deny` (`Read(//…)`) **and** `sandbox.filesystem.denyRead` of a `run`'s settings, beside the vault, the database and the identity. Named: `a registered sink and its sidecar are in both deny lists of a single-connection run and of a pooled run`, `a sink of another pool is denied too (any lane may read any sink)`, `a removed sink leaves the deny list at the next run`, `a run with no sinks has the same deny list as before` (characterisation), `the deny entries are valid Read rules (readRule) for a file that does not exist yet`.

### C. `write-env` (plan 3.6)
7. **File adapter** (`apps/connections/test/env-file.test.ts`, temp directories): `writeEnvFile(path, name, value)` writes `NAME=value\n` through a temp file in the same directory, mode 0600, `rename`, directory fsync best-effort. Named: `the file is 0600 and holds exactly NAME=value`, `a reader never sees a half-written file: the temp file is created 0600 before the value is written, and a failing rename leaves the old file intact and no temp file`, `an existing file's content is replaced, its mode is made 0600`, `a path in a git work tree is refused` (a `.git` directory or file in any ancestor), `a directory writable by group or others is refused` (**deviation** from "world-readable directory", reason below), `a path under the vault is refused`, `a name that is not [A-Z_][A-Z0-9_]* or a value outside the key characters is refused and nothing is written` (no quoting or escaping code exists), `a symlink at the path is refused`, `the sidecar <path>.member holds only the member name, 0600, by the same rename`.
8. **Service and CLI** (`apps/connections/test/key-pool-write-env.test.ts`, `keypool-write-env-cli.test.ts`): `keypool write-env <pool> --file <path> --var NAME [--if-due] [--rotate-every 12h]`. Named: `refuses a path that is not a registered sink of that pool`, `one lease per write: a probe-style gated lease (reserve 0, holder = the writer), KeyServed written before the file, the lease closed after, and the sweep does not reap it`, `the pick follows the pool's order and moves the cursor like lease --pool`, `a member the gate declines is passed over, as for lease --pool`, `an empty or blocked pool writes nothing, leaves the old file and exits 75 with its word`, `stdout and stderr hold words only, never the value, the path or the member's key`, `--if-due does nothing while the sidecar's member is still active`, `--if-due rewrites after the served member is reported exhausted`, `--if-due rewrites when the file or the sidecar is missing`, `--rotate-every rewrites in round-robin only, after that long`, `a planted secret in the environment, the argv and the pool's events leaves nothing in the file or the outputs`, `the written value equals the member's key and no other file of the home holds it`, `a failed write closes the lease with failed and leaves no temp file`.

### D. `watch` (plan 3.6, last paragraph)
9. **Matcher** (`apps/connections/test/log-watch.test.ts`): `lineVerdict(line)` returns `exhausted-credit`, `exhausted-spend` or `none`; it uses the classifier's own `CREDIT` and `SPEND` patterns and no other, and a line longer than 8 KB is cut before it is looked at. Named: `a credit line and a spend-limit line are verdicts, in either wording`, `an ordinary line, a rate-limit line and a hold line are none` (a log holds anyone's words: only the two exhausted phrases act, a hold stays the owner's to find), `the verdict holds no part of the line`, `a very long line is cut, not buffered whole`, `a line split across two reads is joined, a partial last line waits for its newline`.
10. **Service and CLI** (`apps/connections/test/keypool-watch-cli.test.ts`): `keypool watch <pool> --log <file> (--member M | --sink <sink>) [--once]` (the plan's `--env-file` cannot be a flag of this bin: Node reads it anywhere in the argument list) follows the log from its end (`--once`: process what is there now and exit; the test seam and the timer form). Named: `a credit line in the log marks the member exhausted and prints one JSON line of words`, `the matched line is never echoed: stdout, stderr and every file of the home hold none of it` (planted secret in the line), `with --env-file the member is read from the sidecar at each match, so a rotated file is followed`, `a second match for the same member within 10 s reports once`, `a rotated or truncated log is followed from its start`, `a log that is not there yet is waited for`, `an unknown pool or member exits 1 with its word`, `its own output passes the exact-value filter: a key printed by a faulty report would be [redacted]` (a unit on the filtered writer with a deliberately leaking writer, control: the filter removed).

## The directory rule (deviation from the plan's words)
The plan says `write-env` "refuses a path in a world-readable directory". A key file is 0600; what a directory open to others adds is the chance to replace or unlink it. The rule built is: refuse a parent directory that group or others can write (mode `& 0o022`). A world-readable but not writable directory (`/opt/app`, mode 0755) is the usual place for a server's `.env` and stays allowed.
